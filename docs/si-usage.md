# Use of Super Intelligence (SI) in AgroAyuda

NASA Space Apps requires teams to state where and how SI tools (chatbots, large language models, image or audio generators) were used, and to mark SI-generated code, data, audio, images and video. This file is that statement for the whole repository. Each module owner keeps their row up to date; the lead checks it before the final submission.

**Summary.** The idea, the product decisions, the agronomic rules and every crop value are the team's own; crop values come from cited sources, not from an AI. We used AI assistants to organize and review our plan, to help write code and documentation, and for the English voice-over of the video. No NASA branding or design elements are used or generated anywhere in the project.

## Before the event

Before the event, we used an AI assistant (Claude) to organize our ideas into a written plan and to review it, probed the NASA POWER and SoilGrids APIs, and looked at NASA POWER monthly rain normals at one Chiquimula point; no code or datasets from before the event are part of the build. The planning documents in `docs/` (architecture, ADRs, spec, work packages) and `AGENTS.md` were written with AI assistance and carry a dated preface saying so.

## During the event

### Code

AI coding assistants helped write code in every module. A human chose what to build, reviewed every change, ran the tests and merged it; every pull request passes the same quality gate (`make check`: format, lint, strict typing, tests).

| Module | Owner | SI tool(s) used | How |
|---|---|---|---|
| `contracts/`, `api/`, CI, repo setup | Lead | Claude Code (Anthropic) | Scaffolding, contract models from the team's spec, API endpoints, tests written first |
| `data/` pipeline, `engine/src/engine/risks.py` | Data owner | Claude Code (Anthropic) | Pipeline and risk code and tests written test-first with the assistant from the work package; the owner chose N, the cut-offs and the SoilGrids depth, and the region-wide dry-day check was run on real POWER data before any rule was fixed; package 07 (submission docs): the assistant read the OpenFreeMap licence page and edited the rows, with the owners' answers written as given |
| `engine/` | Engine owner | Claude (Anthropic) | Code, tests and documentation drafted with the assistant for almost every task, then reviewed and run by the owner (`make check`) before each merge |
| `web/` map and risks | Web-map owner | Claude (Anthropic) | Code, tests and documentation drafted with the assistant for almost every task, then reviewed and run by the owner (`make check`) before each merge |
| `web/` form and comparison, `data/catalog/rotation_templates.csv`, README | Web-results owner | Claude (Anthropic), in the claude.ai chat | Form, comparison table, detail, API call and tests drafted test-first from the work package and then reviewed and run by the owner (`make check`); the template rows were assembled from `docs/crop-sources.md` and checked against `crops.csv` by a test; the owner confirms the combinations with the lead's curated list |

### Data

| Data | SI-generated? | Notes |
|---|---|---|
| NASA POWER climate (`data/output/*.parquet`, `web/public/data/layers/rain.geojson`) | No | Downloaded from NASA POWER and processed by our pipeline code (the code was written with AI assistance, see above) |
| SoilGrids soil, geoBoundaries region | No | Downloaded from the providers; sources and licences in `data/README.md` |
| Crop catalog `data/catalog/crops.csv`, rotation templates `data/catalog/rotation_templates.csv` | No | Values chosen by the team from cited sources (see `docs/crop-sources.md`); every row names its source |
| Test fixtures `contracts/examples/*.json` | Yes, partly | Written with AI assistance from the team's spec; catalog fixtures are marked "EXAMPLE FIXTURE, not real data" and are never used by the app |
| Text shown to farmers (explanations, reasons) | Partly | Drafted with AI assistance, reviewed and edited by the team; generated by fixed rules in `engine/`, not by an AI at run time |

The app itself does not call any AI service: every recommendation comes from fixed, tested rules.

### Documentation

`README.md`, `docs/` and code comments were written with AI assistance and reviewed by the team.

## Text for the submission form ("Use of Super Intelligence")
